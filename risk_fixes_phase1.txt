Neulifi Phase 1 risk register

This file records fixes deferred because their estimated breakage risk is >= 50%, or because the issue requires controlled reproduction outside this low-risk repair pass.

ISSUE:
Fixed mobile bottom navigation can obscure the first Insights card and CTA in the initial viewport.
LOCATION:
src/index.css: .bottom-nav, .screen, .analytics-tier-grid; shared app layout.
OBSERVED BEHAVIOR:
At 390px, the fixed bottom navigation occupies the lower viewport while the first locked Insights card extends into the same region. The page becomes usable after scrolling, but the initial card/CTA presentation is partially covered.
EXPECTED BEHAVIOR:
Fixed navigation should not obscure visible content or primary actions on any mobile screen.
WHY IT SHOULD BE FIXED:
It weakens first-view comprehension and can hide a paid-feature CTA on mobile.
PROPOSED FIX:
Rework mobile content insets and/or the analytics layout so content reserves the fixed navigation area without creating excessive whitespace or affecting every screen.
ESTIMATED BREAKAGE RISK:
55%.
WHY RISK IS >= 50%:
The navigation is a shared fixed layout component. A global inset or layout change can alter every mobile screen, safe-area behavior, scroll height, sticky/fixed interactions, and the first viewport composition.
AFFECTED SYSTEMS:
Shared mobile navigation, all authenticated screens, analytics layout, safe-area handling, responsive CSS.
RECOMMENDED FUTURE APPROACH:
Capture each mobile screen at 390px, 430px, and real iOS/Android safe-area sizes; define a shared bottom-navigation content inset; verify top, middle, and maximum scroll positions before release.

ISSUE:
Cross-section navigation can retain the previous scroll position.
LOCATION:
App screen navigation and desktop main/mobile document scrolling.
OBSERVED BEHAVIOR:
After scrolling saved detail to the bottom, navigating to Insights preserved a deep scroll position, leaving the Insights title and summary above the viewport.
EXPECTED BEHAVIOR:
Navigating to a new top-level screen should begin at its top unless the user explicitly used browser history to restore position.
WHY IT SHOULD BE FIXED:
Users can land midway through a new section and miss its context or primary controls.
PROPOSED FIX:
Reset the correct scroll container on top-level screen navigation while preserving intentional browser back behavior.
ESTIMATED BREAKAGE RISK:
60%.
WHY RISK IS >= 50%:
Desktop scrolls the main element while mobile scrolls the document. A naïve window.scrollTo change will not cover desktop; a shared effect may interfere with history detail, modals, focus, and browser back restoration.
AFFECTED SYSTEMS:
Global navigation, desktop main scroll container, mobile document scroll, history behavior, accessibility focus.
RECOMMENDED FUTURE APPROACH:
Add a route/screen navigation abstraction with per-container reset rules and verify all screen transitions plus browser back/forward.
